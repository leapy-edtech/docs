## Visão geral

O recurso **Leadership** permite criar e gerenciar **lideranças** — usuários que atuam como gestores de jovens (aprendizes/estagiários) nas empresas parceiras. Lideranças são criadas como usuários no Directus (`directus_users`) com role `user-leadership` e vinculadas a jovens via `user_careers.leader_id`.

---

## Modelo de dados

Uma liderança é composta por:

- **`directus_users`**: registro de usuário com role `user-leadership`, contendo `first_name`, `last_name`, `email` (obrigatórios)
- **`user_personal_data`**: dados pessoais (telefone, etc.)
- **`user_careers`**: relacionamento com jovem (`user_id`) e empresa (`account_id`), incluindo campo `leader_id` (FK para `directus_users.id`)

---

## Criação via API

### Endpoint: `POST /leadership`

Cria uma nova liderança no sistema, incluindo:
1. Usuário em `directus_users` (role `user-leadership`)
2. Dados pessoais em `user_personal_data`
3. Vínculo em `user_careers` (liderança → jovem → empresa)

**Validações obrigatórias:**
- `first_name`, `last_name`, `email` (do usuário liderança)
- `phone_number` (dados pessoais)
- `account_id` (empresa)

**Exemplo de payload:**
```json
{
  "first_name": "Maria",
  "last_name": "Silva",
  "email": "maria.silva@empresa.com",
  "phone_number": "+5511999999999",
  "account_id": "uuid-da-empresa"
}
```

---

## Relações com outros recursos

- **Jovens (Apprentices)**: Vinculados via `user_careers.leader_id`
- **Empresas (Accounts)**: Identificadas via `user_careers.account_id`
- **Directus Users**: Lideranças são usuários com role `user-leadership`

## Troubleshooting — Dados de liderança vazios

### Problema: jovens com liderança sem nome ou e-mail

**Sintoma:** Ao buscar jovens filtrados por turma (ex: `start_date >= 2026-01-01`), alguns aparecem com dados de liderança (`first_name` ou `email`) vazios.

**Causa raiz:**

1. **Migração da tabela legada `Liderancas`:** Antes da migração para o modelo atual, lideranças eram armazenadas na tabela `Liderancas` (com colunas `Nome`, `E-mail`, FK `user`). Durante a migração para o modelo atual (`directus_users` com role `user-leadership` + `user_careers.leader_id`), registros com `Nome` ou `E-mail` NULL podem ter sido migrados com `first_name`/`email` NULL em `directus_users`. A tabela `Liderancas` é legada e será removida.

2. **Criação via `/leadership` com validação bypassada:** A rota `POST /leadership` valida `first_name`, `last_name` e `email` como obrigatórios. Registros criados após a migração **não deveriam** ter campos vazios, mas podem existir casos edge (ex: validação desabilitada temporariamente, imports diretos no Directus).

**Como identificar:**

Query Directus (ou SQL) para listar jovens em turmas iniciadas em 2026 com liderança incompleta:

```
Jovens (filtro: turma.start_date >= '2026-01-01')
  → JOIN user_careers ON user_careers.user_id = Jovens.user
  → JOIN directus_users ON directus_users.id = user_careers.leader_id
  → WHERE directus_users.first_name IS NULL
      OR directus_users.email IS NULL
```

**Correção:**

- **Manual:** Preencher `first_name` e `email` diretamente no registro de `directus_users` da liderança via Directus Admin.
- **Bulk:** Se houver muitos registros, rodar script de backfill consultando fonte de verdade (ex: planilha original ou sistema de RH da empresa).

**Prevenção:**

- A validação atual na rota `/leadership` já previne novos registros vazios.
- Monitorar constraints `NOT NULL` no schema de `directus_users.first_name` e `directus_users.email` (atualmente são nullable por compatibilidade com outras roles; considerar constraint condicional por role no futuro).
